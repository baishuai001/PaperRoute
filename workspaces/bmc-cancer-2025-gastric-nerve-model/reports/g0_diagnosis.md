# 为什么PR #2的推荐不令人满意：PaperRoute、SPP1锚点还是二者共同作用？

## 结论

**是二者共同作用，但责任不同。**

- PaperRoute v0.1.0-alpha.1 的G0定义不够硬，允许审计者从“锚点故事”较快跳到一个听起来
  新颖的方向，却没有先证明：锚点适合提供什么、候选稿的唯一内核是什么、决定性图是什么、
  初学者必须新增多少代码，以及什么结果会否定方向。
- SPP1+TAM锚点本身高度机制化、主题拥挤、实验与私有资源依赖强。它适合作为跨尺度证据
  结构或生物学故事的donor，却不是初学者获得“高质量完整代码 + 全公开数据”的理想donor。
- 两者叠加后，PR #2的推荐从具体SPP1问题跳到“多个髓系状态的跨队列可转运性”。这个
  建议并非逻辑错误，但与锚点的可辨认主线距离变大，稿件的中心命题、决定性结果和学习
  路径没有被压缩到足够清楚，所以容易让人感觉“workflow在自行另起题目”。

## 1. PaperRoute原G0缺了什么

原文档已经要求创新性、可行性、fatal veto、claim ceiling和主/备方向，这些原则是对的。
但缺少五个会直接改变推荐的强制产物：

1. **锚点适配性分类**：分别判断设计、数据、方法、代码和结论是否可复用；
2. **构念有效性地图**：论文的关键词标签是否被直接测量，还是只是基因集命名；
3. **证据独立性地图**：发现、筛选、拟合、阈值和验证是否复用了同一批患者；
4. **稿件内核**：一句话问题、分析单位/estimand、决定性图、falsifier和最低数据/代码；
5. **初学者执行预算**：需要新增多少数据适配、统计方法和自写核心代码，哪些地方必须由
   高质量donor承接。

这些要求现已写入通用`docs/workflow.md`。它们不是为了无限优化workflow，而是为了在G0
直接拦截会浪费数月的数据下载和代码开发。

## 2. SPP1+TAM锚点的固有限制

SPP1+TAM论文属于强叙事、跨尺度、带机制和干预的研究。对初学者有三重错配：

- **创新空间错配**：SPP1巨噬细胞、免疫抑制、转移和免疫治疗已经拥挤；简单换癌种、换
  髓系细胞或再做SPP1富集很难构成新贡献。
- **证据负担错配**：锚点最有说服力的部分通常来自空间、动物、阻断/治疗和私有样本；
  公开计算数据只能复现其中一层。
- **代码donor错配**：即使分析思路好，如果作者代码缺失或碎片化，初学者无法把整篇论文
  当成稳定模板，只能拆成模块，从同类高质量代码补齐。

所以SPP1锚点不是“坏论文”，而是**不适合同时承担题目、方法、代码和数据四种模板**。
它更适合作为设计结构donor和研究问题参照。

## 3. 新BMC案例提供了什么诊断信息

BMC胃癌论文与SPP1论文几乎相反：公开bulk数据多、分析语法简单、机制证据弱、作者代码
缺失。它暴露出PaperRoute必须在方向推荐之前问“这个名字真的被测到了吗”。

| 比较维度 | SPP1+TAM锚点 | 胃癌NRRS锚点 |
| --- | --- | --- |
| 最强价值 | 跨尺度机制叙事和证据架构 | 公共队列索引和可冻结的8基因公式 |
| 主要风险 | 主题拥挤、实验负担高、公开数据无法闭环 | 构念薄弱、队列复用、实现缺失、全景式附加分析 |
| 适合借鉴 | 设计/故事结构、验证层次 | 数据入口、修复问题、基础生存分析训练 |
| 不适合借鉴 | 直接做另一个SPP1机制故事 | 再造一个主题签名并声称机制/治疗 |
| 初学者主线 | 需大幅限界，难度仍高 | 可做冻结分数的有效性审计，难度中等 |

第二个案例表明，PR #2不满意并非“只要换一篇论文就会自动解决”。PaperRoute必须先判定
锚点角色，再生成方向；锚点也必须按目标选择，而不是默认一篇好文章就是好模板。

## 4. 修正后的选择逻辑

以后每次引入文献A，先做以下分解，而不是在“用A的数据还是流程”之间二选一：

| 模块 | 可能来源 | 审查问题 |
| --- | --- | --- |
| 科学问题/不变量 | A或领域缺口 | 是否有可证伪的新问题，而非改名？ |
| 研究设计 | A或文献B | 分析单位、对照、发现/验证和证据尺度是否正确？ |
| 数据 | A、公共数据库或文献C | 可访问、独立、元数据完整、目标人群匹配吗？ |
| 方法 | 官方方法论文/包 | 方法假设是否匹配数据和estimand？ |
| 代码 | A、B或官方workflow | 可运行、版本化、模块化、可测试、统计单位正确吗？ |
| 结果解释 | 预注册claim ceiling | 关联、预测、机制和因果是否被混用？ |

因此允许以下组合：用A定义问题，用B提供成熟分析框架，用C提供独立数据，用官方包承担
核心统计实现，再由PaperRoute记录每个模块为什么可以拼接。所谓“模仿一篇论文”不再意味着
整篇绑定一个来源。

## 5. 这次对PaperRoute做了哪些最小修复

本次只做会影响稿件方向的修复，没有扩展成通用科研平台：

- 根目录保留通用workflow；每篇论文迁入独立`workspaces/<slug>/`；
- G0增加锚点适配性、构念有效性、证据独立性、稿件内核和初学者预算；
- 新案例明确区分主稿路线、条件备选、方法储备和训练复现；
- 候选方向必须写falsifier、最低数据、最低代码donor和fatal veto；
- G0仍由项目负责人批准，不因AI推荐自动进入下载或分析。

如果这套修正应用到下一篇完全不同类型的论文仍产生模糊、漂移或不可执行的方向，才说明
还需要继续改workflow；不应仅凭单个案例无限添加字段。

## 6. 当前可检验的判据

对本次新案例，PaperRoute修复是否有效，可以用四个问题审查：

1. 你能否用一句话复述`DIR-002`的稿件问题，而不会误以为要再建一个神经签名？
2. 你能否指出主方向的决定性结果和可能否定它的结果？
3. 你能否看到每个队列为何是训练、非独立、真正外部、条件空间或不适用？
4. 你能否在下载数据前判断代码donor和工作量是否超过初学者边界？

若其中任一答案仍是否，应该在G0评审中要求修改，而不是进入G1后靠更多分析补救。
